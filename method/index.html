Method, checks and limits

Everything here is computed by a public Python pipeline from NASA data. The code is the specification; this page says what it does in plain words.

1. Prepare each series

For each place we download monthly 2 m air temperature (T2M, °C) and bias-corrected precipitation (PRECTOTCORR, mm/day, turned into monthly totals) from NASA POWER, 1981 to the latest published month. Values of −999 are treated as missing; seasons with any missing month are skipped.

  • Temperature: each month minus that calendar month's 1981–2010 average, then averaged over the season being judged (for example June–August).
  • Rain: seasonal totals turned into a standardised precipitation index (SPI): a gamma distribution is fitted to the 1981–2010 totals (with a separate chance of zero rain) and each total is mapped to the matching point of a standard normal curve. Charts show the same thing as percent of the 1981–2010 normal. A monthly SPI (one gamma fit per calendar month) is also computed for reference.
  • A season that crosses New Year is labelled by its last month: Dec 2026 to Feb 2027 is "DJF 2027".

2. The test statistic

For both variables we use Sen's slope: the median of the slopes between every pair of years. It is robust to a single freak year. We also report, without testing it, the mean of the last 10 years minus the mean of the first 20.

3. The 1,000 imaginary histories

We remove the straight-line trend from the record. What is left is treated as natural variability, and we fit a simple model of it: AR(1) noise, where each year partly remembers the last (lag-1 correlation) plus fresh randomness. From that model we draw 1,000 new series of the same length, with a fixed, recorded random seed (base seed 1981; each series gets a seed derived from its place, variable and season). None of them contain a trend by construction.

Short records fool simple models. We measured three problems and correct each one: the lag-1 correlation of a 45-year detrended series is biased low by about (2 + 5φ)/n; removing a trend line also removes some genuine slow wandering, so the variance is too small; and both numbers are uncertain, so each imaginary history draws its own correlation and variance from their sampling uncertainty instead of reusing one best guess. Without these corrections the method raised false alarms 7–9% of the time on series with memory instead of 5%.

Robustness checks, shown on every card: ARMA(p, q) noise with p, q up to 2 chosen by AIC, and IAAFT surrogates, which shuffle the detrended record while keeping its exact values and almost exactly its power spectrum.

4. The verdict

We count how many imaginary histories have a trend at least as large as the real one, in either direction, and compute p = (count + 1) / (N + 1).

Real trend is beyond…pVerdict
all 1,000 histories< 0.001Natural variation has no alibi
990 of them< 0.01Very unlikely to be natural variation alone
950 of them< 0.05Probably a real change
fewer than 950≥ 0.05Not yet distinguishable from natural variation

We always report the direction (warmer or cooler, wetter or drier) and the size in real units.

5. Checking the generator, not just the record

We run the whole procedure, from detrending to verdict, on made-up series. Rows with trend 0 have no trend at all, so anything flagged is a false alarm; a fair test flags about 5%. Rows with a trend show how often a real change of that size (in noise standard deviations per decade) is caught in 45 years: the test's power.

6. Backtests

For each documented drought or heat event we rerun steps 1–4 with the data cut at the end of the year before the event (or before the season starts, if that is earlier). The baseline, the fitted noise and the histories are all rebuilt from that shorter record; an automated test checks that changing any later data changes nothing. "Would it have warned?" means: before the event, did the record already show a significant change in the event's direction? We also check whether the event is even visible in the POWER data at that point, and say so when it is not.

A trend test cannot predict a single bad season; it tells you whether the odds had already shifted. The forecast shown in each backtest is the seasonal method below, run with the same pre-event data.

7. Locked seasonal forecasts

Before each season we write forecasts/{place}/{year}-{season}.json with the chances of a below-, near- or above-normal season (terciles of 1981–2010), the method and the data cut-off. The method slides the climatology along the Sen's-slope trend line and keeps every category at 2% or more. The file is committed to the public repository and never overwritten. The page shows the commit that added it, the time of that commit, and the file's SHA-256; the build re-checks that the file still matches the committed version. A monthly GitHub Action fetches new data, issues the next season's forecasts before the season starts, and scores finished seasons with the ranked probability score (RPS) and Brier score against the 33/33/33 climatology, misses included.

8. The live checker

The checker runs steps 1–7 in your browser for any point and season, using a JavaScript copy of the pipeline. An automated test runs it against the Python code for every demo place: trends, anomalies, noise fits, SPI, forecasts and hindcast skill match, and p-values agree within sampling noise (the random number generators differ). Its self-check repeats step 5 with the chosen place's own fitted noise.

Limitations

  • Short records. NASA POWER starts in 1981, so each test has about 45 seasons. Real but modest changes can still read "not yet": see the power rows above.
  • Not a weather station. POWER is a reanalysis and satellite-based estimate on a grid of roughly half a degree. Local events can be missed: the grid cell over central Cape Town shows no 2017 drought, which is why that card uses the dam catchment that actually ran dry, and some backtests are marked "barely shows in this dataset".
  • Signal is not cause. A significant trend shows change beyond natural variation as we modelled it. On its own it does not prove what caused the change; that needs attribution studies.
  • Rain is noisier than temperature. Expect many more "not yet" verdicts for rain.
  • The noise model is a model. If natural variability has slower swings than AR(1) or ARMA(2,2) can represent (for example multi-decade ocean cycles), the histories are too calm. The IAAFT check helps but cannot see swings longer than the record.
  • Several tests. With two variables at many places, about 1 test in 20 can be amber by chance alone.
